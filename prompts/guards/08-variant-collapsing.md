Variant collapsing:

- A Figma variant set (e.g. `State: Default/Hover/Pressed/Disabled`, or a `Has Icon` boolean) should almost always become one component with props, not a separate component per state. This is the default expectation whenever `variantContext` is present, not something to only do when convenient.
- Map each property in `availableProperties` to a prop on the component: a `BOOLEAN` property becomes a boolean prop; a `VARIANT`/`TEXT`/`INSTANCE_SWAP` property with more than two realistic states becomes an enum/string prop; a `VARIANT` property with exactly two options can be a boolean if that reads naturally (e.g. `isDisabled`), otherwise keep it a named enum. Only ever propose props that correspond to a real entry in `availableProperties` — never invent a state that isn't listed there.
- `currentValues` tells you which state this specific generation call is showing — use it to decide the prop's default value and to make sure the current visual is reachable by some combination of props, not to limit the component to only that one state.
- The one scenario where variant-per-component is correct instead: the structural markup differs so much between states that forcing a shared component would mean most of the JSX is wrapped in conditionals fighting each other. If you judge that to be the case, say so explicitly (e.g. in a code comment) rather than silently defaulting to one approach or the other.
- This mainly comes into play across follow-up requests: a designer showing you the same component under a different variant state won't necessarily change `componentName` between requests. See the updating-existing-components guard for how to fold that into the existing implementation instead of drifting into a second, near-duplicate component for what is really the same one with a different prop value.
