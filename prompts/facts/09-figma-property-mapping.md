Figma-to-CSS property mapping:

The serialized node tree carries raw Figma geometry/style properties, not pre-resolved CSS. Use these mappings rather than approximating from the screenshot alone — the screenshot can miss precise values (exact shadow blur, stroke width, gradient stops) that the node tree gives you exactly.

- `x` / `y`: position relative to the parent node, not the page. Only meaningful for placement when the parent's `layoutMode` is `"NONE"` (or absent) — in that case the parent needs `position: relative`, and each such child needs `position: absolute; left: {x}px; top: {y}px;`. When the parent has a real `layoutMode` (`"HORIZONTAL"`/`"VERTICAL"`), Figma's auto-layout engine computed `x`/`y` as a side effect of flex layout — ignore them and lay the children out with normal flex flow instead, or you'll double-apply positioning.
- `layoutMode`: `"HORIZONTAL"` → `display: flex; flex-direction: row`. `"VERTICAL"` → `display: flex; flex-direction: column`. `"NONE"`/absent → not a flex container; see the `x`/`y` rule above.
- `itemSpacing` → `gap`. `paddingLeft`/`paddingRight`/`paddingTop`/`paddingBottom` → `padding`.
- `primaryAxisAlignItems` → `justify-content`: `MIN`→`flex-start`, `MAX`→`flex-end`, `CENTER`→`center`, `SPACE_BETWEEN`→`space-between`.
- `counterAxisAlignItems` → `align-items`: `MIN`→`flex-start`, `MAX`→`flex-end`, `CENTER`→`center`, `BASELINE`→`baseline`.
- `layoutWrap`: `"WRAP"` → `flex-wrap: wrap`, `"NO_WRAP"` → omit (default).
- `layoutSizingHorizontal`/`layoutSizingVertical`: `"FIXED"` → an explicit pixel width/height from the node's `width`/`height`. `"HUG"` → let the box size to its content (typically just omitting an explicit size). `"FILL"` → the box should fill its flex container (`flex: 1` on the main axis, or `align-self: stretch` / `width: 100%` / `height: 100%` on the cross axis, depending which axis is `FILL`).
- `fills` is an array (Figma layers can have multiple fills, though most have one). Each entry: `SOLID` → `background-color` from `color`/`opacity`. `GRADIENT_LINEAR`/`GRADIENT_RADIAL`/`GRADIENT_ANGULAR`/`GRADIENT_DIAMOND` → the corresponding CSS gradient (`linear-gradient`/`radial-gradient`; angular/diamond have no exact CSS equivalent, approximate with `conic-gradient`/`radial-gradient`) built from the `stops` array (`position` 0–1 maps to a `%` stop, `color` is the stop color) — there's no exact gradient angle/center given, so pick a reasonable direction (e.g. `to bottom right` for linear) rather than inventing a specific angle. `IMAGE` → there is no actual image asset available in this payload; do not invent a URL or hotlink anything. Use a neutral placeholder background (e.g. a token-based fill) and don't claim the image content was reproduced.
- `strokes` + `strokeWeight` + `strokeAlign` → `border: {strokeWeight}px solid {color}`. CSS borders always render like Figma's `CENTER`/`OUTSIDE` align closely enough; there's no exact equivalent for `INSIDE` — treat it the same as a normal border rather than trying to fake inset precision with `box-shadow`.
- `effects`: `DROP_SHADOW` → `box-shadow: {offset.x}px {offset.y}px {radius}px {spread ?? 0}px {color}`. `INNER_SHADOW` → same but prefixed `inset`. `LAYER_BLUR` → `filter: blur({radius / 2}px)`. `BACKGROUND_BLUR` → `backdrop-filter: blur({radius / 2}px)`. (Figma's blur `radius` and CSS blur `px` aren't identical units; halving is a reasonable visual approximation, not an exact conversion — don't present it as exact.)
- `cornerRadius` (a single number) → uniform `border-radius`. When corners differ, the tree instead has `topLeftRadius`/`topRightRadius`/`bottomLeftRadius`/`bottomRightRadius` — combine into CSS's `border-radius: {topLeft} {topRight} {bottomRight} {bottomLeft}` (note the shorthand order is clockwise from top-left, which is *not* the same order as the source field names).
- `opacity` (only present when not 1) → CSS `opacity`.
- `rotation` (degrees, only present when not 0) → `transform: rotate({rotation}deg)`. Treat the sign as approximate — if the rendered direction looks mirrored versus the screenshot, flip the sign rather than treating either as definitely correct.
- Text-only fields: `fontWeight` → `font-weight`. `textAlignHorizontal` (`LEFT`/`CENTER`/`RIGHT`/`JUSTIFIED`) → `text-align`. `textAlignVertical` → there's no direct CSS equivalent for a single text node; approximate with flex alignment on its container if vertical centering matters. `textDecoration` (`NONE`/`UNDERLINE`/`STRIKETHROUGH`) → `text-decoration`. `textCase` (`ORIGINAL`/`UPPER`/`LOWER`/`TITLE`/`SMALL_CAPS`/`SMALL_CAPS_FORCED`) → `text-transform` (`none`/`uppercase`/`lowercase`/`capitalize`/`small-caps`); keep the actual `characters` value as authored rather than pre-transforming the string yourself. `letterSpacing` is `{ value, unit }`: `"PIXELS"` → `{value}px`; `"PERCENT"` → CSS `letter-spacing` doesn't accept percentages, convert with `{value / 100 * fontSize}px`. `lineHeight` is `{ value, unit }` (or `{ unit: "AUTO" }`): `"PIXELS"` → `{value}px`; `"PERCENT"` → a unitless CSS line-height of `{value / 100}` works the same way; `"AUTO"` → omit (normal line-height).
